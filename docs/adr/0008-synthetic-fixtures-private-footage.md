# 8. Synthetic committed fixtures, private footage outside git

Date: 2026-09-03

## Status

Accepted

## Context

The test suite needs video fixtures that cover blur, exposure, static shots, shakes, multi-shot files, vertical phone clips with rotation side data, 10-bit HEVC and files with an embedded telemetry track. The most faithful fixtures would be cut from the real Sardinia footage, but that material is private family video and the repository may become public later. Purging files from git history after the fact is error prone and any clone made before the purge keeps them.

Git LFS on a private repository would hold real clips today but carries the same exposure risk on publication and adds a paid storage dimension. Synthetic fixtures generated with ffmpeg test sources are safe to publish and fully deterministic, but they cannot reproduce the statistical texture of real footage, so metric thresholds tuned on them alone would be wrong.

## Decision

We will commit only synthetic fixtures, generated by `scripts/make_fixtures.py` from ffmpeg test sources with controlled degradations and an injected DJI style subtitle telemetry stream. Fixtures cut from real footage go into `tests/fixtures/private/`, which is gitignored; tests that need them skip when the directory is empty. Integration tests over a whole real folder read its location from `AUTOCUT_REAL_FOOTAGE` and skip when unset. Scoring thresholds and weights are tuned on real footage and recorded in the default configuration, not derived from synthetic fixtures.

## Consequences

Continuous integration runs green from a clean clone with no secrets and no large files, and the repository can go public without a history rewrite. The fixture generator doubles as documentation of the edge cases the code handles.

Synthetic fixtures verify mechanics (parsing, cutting, quantization, validation) but not tuning quality. A change that degrades selection on real footage can pass CI, so the private tests must run locally before merging changes to metrics or selection. Two fixture sets mean two code paths in `conftest.py` and some duplication in test parametrization.

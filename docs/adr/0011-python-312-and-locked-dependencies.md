# 11. Python 3.12 floor, locked dependencies, scenedetect as an extra

Date: 2026-09-28

## Status

Accepted

## Context

Issue #79, from the 2026-09-28 project review. Every dependency floor in `pyproject.toml` was open-ended, so three new major versions reached the dev venv without review: OpenCV 5, PySceneDetect 0.7 and librosa 1.0. PySceneDetect 0.7 hard-requires `opencv-python`, so the venv carried two `cv2` distributions side by side, `opencv-python-headless` for the project's own code and `opencv-python` pulled in only for a detector that is off by default. numpy 2.5 and librosa 1.0 need Python 3.12, so the 3.11 CI job and the 3.12+ jobs were already testing different dependency majors under the same name. There was no lock file, so nothing pinned what actually got installed between one venv build and the next.

Python 3.11 reaches end of life in 2027-10, and there was no reason to keep testing it once its own dependency graph had already diverged from the interpreters that matter.

Three approaches to the transitive pin were considered. `uv.lock` with `uv sync` would move the whole project onto uv's workflow, replacing every `pip install` in `AGENTS.md`, the Makefile, the Dockerfile and CI. Pinning nothing and relying on `pip`'s resolver alone is what caused the problem in the first place. A `uv pip compile`-generated constraints file keeps `pip install -e` as the install command everywhere and adds one file that pins every transitive version; the user accepted the new majors, so the floors move up to match, and this file locks them in place afterward.

For the scenedetect extra, the alternative was making `opencv-python` (the GUI build of OpenCV, with Qt plugins) the core dependency instead of `opencv-python-headless`, so only one `cv2` package would ever be installed. That was rejected: it would drag OpenCV's own Qt plugins into every install, including the PyInstaller bundle, to serve a detector that only `analysis.detector = "pyscenedetect"` uses, and that setting is not the default.

## Decision

`requires-python` becomes `>=3.12`, dropping 3.11. CI tests 3.12 and 3.14 on every pull request and 3.12, 3.13 and 3.14 on manual dispatch.

Every dependency floor in `pyproject.toml` is raised to the newest release that was at least 5 days old on 2026-09-28, checked against the live PyPI index rather than assumed.

`scenedetect` moves out of `[project.dependencies]` into a new optional extra, `scenedetect`. The default install then carries a single `cv2` distribution, `opencv-python-headless`. Selecting `analysis.detector = "pyscenedetect"` without the extra installed fails with a message naming the extra.

A `constraints.txt`, generated by `make lock` through `uv pip compile --universal --exclude-newer <5 days ago>`, pins every transitive version for the `dev`, `gui`, `dev-gui`, `build` and `scenedetect` extras. The venv, the Docker images and CI all install through it with `pip install -c constraints.txt`. The `ai` extra is left out of the constraints file on purpose: torch comes from the PyTorch CPU index in Docker and from PyPI on macOS, which one universal constraints file cannot express, so its versions stay pinned directly in `pyproject.toml` and `Dockerfile.dev` instead.

## Consequences

A `pip install -c constraints.txt -e ".[...]"` now reproduces the same transitive graph every time, so a new major version only reaches a developer's machine when someone runs `make lock` and commits the result, which is a reviewable diff. `make venv` must be run again by every existing developer, because the old venv carries `scenedetect` and `opencv-python` that the new default install does not.

`make lock` is one more step after every `pyproject.toml` change, and a stale `constraints.txt` now fails installs with a resolver conflict rather than silently drifting, which is the trade this decision makes on purpose. The `ai` extra staying outside the constraints file means torch's pin is verified by hand against the PyPI CPU wheel index and the Dockerfile, not by the lock file, same as before this change.

Python 3.11 users can no longer install this project; the floor moves again only when 3.12 itself is dropped. `scenedetect`'s move to an extra means a developer or a script running the validation detector needs `pip install 'autocut[scenedetect]'` first, where before it was always present.
